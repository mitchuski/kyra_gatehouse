How it works

Seven stations, four guardrails, one rule everywhere: the gate says yes or no on the record.

1 · Approach — spoof refusal

An identity that does not verify is refused before assessment. For did:key, the DID must bind its own public key; the refusal itself is an audit event. Identity providers are pluggable adapters — the core never depends on any one stack.

2 · Assess — evidence, not self-assertion

24 probes derive from the model (never a fixed checklist): 12 probe the four forces an agent must hold — protect, project, reflect, connect — and 12 probe the six pairwise separations between them. Six probes are selected for deep verification by a draw seeded from the sha256 of the agent's own canonicalised submission: the agent cannot know which probes will be probed while it writes, and any auditor can re-derive the draw.

3 · Challenge — understanding as key

Authentication by comprehension, not possession. The supervisor sets concept anchors and a committed proverb (a hash — the secret is never stored). The agent must answer in its own words: echoing the prompt scores zero; presenting the commitment scores zero. Every attempt is ledgered before it is judged — failure is as permanent as success.

4 · Approve — the human in the loop

No credential issues without a supervisor approval carrying a written rationale, recorded as a chained audit event. This is a gate, not a rubber stamp: withholding it sandboxes the agent regardless of its scores.

5 · Issue — the bilateral credential

A Verifiable Relationship Credential (W3C VC 2.0 shape) issues only when BOTH gates passed. It carries exactly two proofs — issuer and subject; unforgeable alone — and every piece of evidence in it points at a verified audit event. Verdicts are a closed lexicon: VALIDATED → fly, MIRAGE → sandbox, BLOCKED → hold. A sandboxed agent runs credential-less under a capped manifest; a held agent does not run at all.

6 · Deploy — scope by variance

The granted capability set and its TTL are a function of det(Σ) and the agent's lattice stratum — high volume earns broad scope, low volume a sandbox, collapsed volume nothing. The same config numbers that gate deployment print the policy a regulator reads (a Lexon-style controlled-natural-language term; correspondence is tested).

7 · Revoke — and audit, always

Every state transition is a content-addressed event chained to the prior one — same bytes, same hash. The supervisor's dashboard recomputes the chain in the browser: flip one byte and the break is visible locally, without trusting any server. Revocation flips a status-list entry and fails the credential for every relying party, immediately.
