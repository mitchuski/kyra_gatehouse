## The workflow, made to make sense (dashboard v4)

The v3 cockpit had all the machinery but assumed the operator knew the
ceremony by heart. v4 teaches it as it runs:

1. **Named stations, not numbers.** Scenes are now *the gate · assessment ·
   understanding · the two gates · decision · the pool · revocation* — the
   same seven names everywhere (station rail, queue mini-rails, scene
   headers). The assessment scene absorbed the instrument triptych (score →
   draw → instruments is ONE thought, one card).
2. **The station rail + next action.** Selecting an agent shows its rail
   with the current station lit and a single guiding line — "▸ next: write a
   rationale and approve — gate 1 is yours alone", or a pulsing "◌ waiting
   for the agent's answer (it acts from /agent/ on its own)…". The active
   scene card glows. Nobody has to guess the next click, ever.
3. **The walkthrough (self-ticking).** A sidebar checklist of the ten demo
   beats — spoof refused → AURORA admitted → assessed → answered → issued →
   MIRAGE sandboxed → bundle to Beta → accepted → revoked → propagation —
   each ticking itself FROM ENGINE STATE across both authorities (never
   clicked). 10/10 means the video captured everything; the tamper demo is
   listed as the one manual, client-side item.
4. **The two-gates panel gained the third light.** Approval · understanding
   · **the volume** (det against the live fly threshold) — so the MIRAGE
   outcome reads as what it is: two gates open, the third decides.
5. **Guided seams.** Transmitting a bundle raises "switch to Authority Beta
   to verify it"; Beta's empty states explain what will arrive and why;
   approve only offers itself once gate 2 has passed; reset asks first;
   button copy tells the truth ("score as observed", "mimicry test: echo the
   prompt (scores 0)", "or transcribe an in-person answer").
